# דוח בדיקת עומס - Hotzla

## 1. מטרת הבדיקה

מטרת הבדיקה היא לוודא שמערכת Hotzla נשארת יציבה ומהירה תחת עומס של **100 משתמשים בו-זמנית**, אשר מבצעים את תהליך ההזמנה המרכזי במערכת:

1. גלישה בקטלוג המוצרים.
2. פתיחת עמוד מוצר.
3. חישוב מחיר בזמן אמת תוך שינוי כמות או מאפייני המוצר.
4. הוספת מוצר לעגלת הקניות.
5. שליחת ההזמנה.

### תנאי הצלחה

| מדד                             | יעד                 |
| ------------------------------- | ------------------- |
| מספר משתמשים וירטואליים במקביל  | 100                 |
| זמן תגובה p95 כללי              | פחות מ-500ms        |
| שיעור בקשות HTTP שנכשלו         | פחות מ-1%           |
| שיעור תרחישי משתמש מלאים שנכשלו | פחות מ-1%           |
| שימוש CPU של השרת               | יש למדוד ממוצע ושיא |
| שימוש בזיכרון של השרת           | יש למדוד ממוצע ושיא |

בנוסף למדד הכללי, בדיקת k6 מודדת את זמן ה-p95 בנפרד עבור:

- טעינת הקטלוג.
- טעינת פרטי מוצר.
- חישוב מחיר.
- הוספה לעגלה.
- שליחת הזמנה.

## 2. כלי הבדיקה

בדיקת העומס משתמשת ב-**k6**.

k6 הוא כלי לבדיקות עומס שמאפשר לדמות מספר גדול של משתמשים אשר שולחים בקשות לשרת במקביל.

ב-k6 כל משתמש מדומה נקרא:

```text
Virtual User (VU)
```

בבדיקה זו מוגדרים 100 משתמשים וירטואליים אשר מריצים במקביל את תהליך ההזמנה מתוך:

```text
tests/load/k6-script.js
```

הבדיקה היא בדיקת עומס ברמת HTTP/API.

כלומר, היא אינה פותחת בפועל 100 חלונות דפדפן, אלא שולחת לשרת את אותן בקשות שה-Frontend היה שולח בזמן שימוש רגיל במערכת.

גישה זו מאפשרת לבדוק את ביצועי ה-Backend וה-Database בצורה יעילה ומדויקת יותר.

## 5. הרצת הבדיקה

לפני הרצת הבדיקה יש לוודא:

- שרת ה-Backend של Hotzla רץ.
- PostgreSQL רץ.
- קיימים מוצרים פעילים בקטלוג.
- `AUTH_MODE=mock` מוגדר בסביבת הבדיקה.
- קיים לפחות מוצר אחד שניתן להזמין ללא `FILE_UPLOAD` חובה.
- מערכת המייל מוגדרת לסביבת בדיקה בטוחה.

### הרצה ראשונית

מומלץ להתחיל עם בדיקה קטנה של שני משתמשים בלבד.

מתיקיית השורש של פרויקט Hotzla:

```powershell
$env:BASE_URL="http://localhost:8080"
$env:VUS="2"
$env:DURATION="30s"

k6 run tests/load/k6-script.js
```

הבדיקה הזאת מדמה שני משתמשים למשך 30 שניות.

המטרה היא לוודא שכל ה-endpoints וה-request bodies תואמים למערכת לפני שמריצים את הבדיקה המלאה.

### הרצת בדיקת העומס המלאה

```powershell
$env:BASE_URL="http://localhost:8080"
$env:VUS="100"
$env:DURATION="5m"

k6 run tests/load/k6-script.js
```

המשמעות היא:

```text
100 משתמשים וירטואליים משתמשים במערכת במקביל במשך 5 דקות.
```

### שימוש במוצר מסוים

אם רוצים שכל הבדיקה תנסה להשתמש במוצר מסוים:

```powershell
$env:PRODUCT_ID="<product-uuid>"

k6 run tests/load/k6-script.js
```

### משתני סביבה זמינים

| משתנה                  | ברירת מחדל                 | שימוש                      |
| ---------------------- | -------------------------- | -------------------------- |
| `BASE_URL`             | `http://localhost:8080`    | כתובת ה-API                |
| `VUS`                  | `100`                      | מספר המשתמשים הווירטואליים |
| `DURATION`             | `5m`                       | משך הבדיקה                 |
| `USER_PREFIX`          | `k6-requester`             | Prefix למשתמשי Mock        |
| `CUSTOMER_UNIT`        | `LOAD_TEST`                | יחידה שתישמר בהזמנה        |
| `BUDGET_OFFICER_EMAIL` | `eitantestemail@gmail.com` | כתובת קצין תקציב לבדיקות   |

## 7. משמעות p95

הדרישה המרכזית בבדיקה היא:

```text
p95 < 500ms
```

p95 הוא האחוזון ה-95 של זמני התגובה.

לדוגמה, אם בוצעו 1,000 בקשות:

```text
p95 = 420ms
```

פירוש הדבר הוא שלפחות 95% מהבקשות הסתיימו בתוך 420ms.

ייתכן ש-5% מהבקשות היו איטיות יותר.

אם התוצאה היא:

```text
p95 = 620ms
```

הבדיקה אינה עומדת בדרישה של פחות מ-500ms.

## 8. מדידת CPU וזיכרון

k6 מודד את זמן התגובה של הבקשות ואת ביצועי ה-HTTP.

הוא אינו יודע כמה CPU או RAM צורך שרת Hotzla.

לכן יש למדוד את משאבי השרת במקביל להרצת k6.

יש להתחיל את ניטור המשאבים מיד לפני תחילת הבדיקה ולהפסיק אותו לאחר סיום הבדיקה.

### אם ה-Backend רץ בתוך Docker

ב-Terminal נוסף:

```powershell
docker stats <backend-container-name>
```

יש לתעד:

- CPU ממוצע.
- CPU מקסימלי.
- שימוש ממוצע בזיכרון.
- שימוש מקסימלי בזיכרון.

### אם ה-Backend רץ כ-Node Process ישירות ב-Windows

ניתן להשתמש ב-Task Manager, Performance Monitor או PowerShell.

לדוגמה:

```powershell
Get-Counter `
  "\Process(node*)\% Processor Time", `
  "\Process(node*)\Working Set - Private" `
  -SampleInterval 1 `
  -Continuous
```

בסביבת Staging עדיף להשתמש במערכת הניטור הקיימת של השרת, אם קיימת.

```text
GET /api/products
        ↓

        ↓

        ↓

        ↓
POST /api/pricing/calculate
        ↓
POST /api/cart/items
        ↓
```
